# Patched upstream crates

Six crates the app builds on are vendored here, each with Lattice's changes, and swapped in through the workspace manifest's `[patch]` tables.
Each is upstream's source at an exact pin plus the diffs in this directory, nothing else; `script/check-patches` rebuilds them from upstream and fails on any difference (CI runs it), and `script/check-patches --write` rebuilds them after a diff is edited or a pin moves.

What is copied: each crate's sources, manifest, build script, README and license (a copy of the repository's, which upstream links), without examples, benches and docs, and for the crates.io crates without their packaging files (`Cargo.lock`, `Cargo.toml.orig`); `gpui-base` keeps the tests and benches its manifest names.
The vendored copies cannot run their own tests where they sit (the gpui crate's tests read examples and fonts that are not copied), so the tests the diffs add run in a gpui-fast checkout at the pin with the diffs applied: the `gpui-patches` workflow does that on every change to this directory, and the command is under "Moving a pin" below. The whole gpui test suite passed against these diffs when they were written (852 tests).

## The diffs

- **`gpui-fast-vendoring.diff`**: what it takes to build the three gpui-fast crates out of their repository.
  `gpui-fast/Cargo.toml` is gpui-fast's workspace manifest, kept so the crates inherit exactly the dependencies and features they do upstream; its members are cut to the three vendored crates, every other gpui-fast crate it names is taken from gpui-fast's git repository at the pin, and its `[patch]` and `[profile]` tables (which only a root workspace reads) are dropped.
  `crates/gpui/Cargo.toml` loses its `[[example]]` entries, whose files are not copied.
- **`gpui-fast-lab-occlusion.diff`**: with `GPUI_LAB_IGNORE_OCCLUSION` set, a window renders as if visible when none of it is on screen (covered, or on a locked display): it is paced by the display's `CVDisplayLink` instead of a `CAMetalDisplayLink`, which stops for a layer that is not on screen, and reports itself visible. Lattice's perf lab measures WebKit the same way. Without the variable the crate behaves as upstream.
- **`gpui-fast-lab-assume-key.diff`**: with `GPUI_LAB_ASSUME_KEY` set, every window acts as the key window of the active app, as GPUI's own test platforms make activation a flag: it reports itself active from the start and stays active when AppKit takes the key window from it (becoming key for real still runs as upstream, so what observes activation, such as a webview handing the keyboard back to GPUI's view, runs), activating a window only orders it forward among the app's windows, and activating the app does nothing.
  So a window's focus, carets, cursor blink and frame rate are a key window's while the app stays in the background, and `script/e2e` runs side by side take the machine-wide input lock only for the steps that need what macOS serves just the real key window (the input method, a webview's keyboard focus, the menu bar's key equivalents); `crates/lattice-gpui/src/scenario/input_lock.rs` has which.
  Without the variable the crate behaves as upstream.
- **`gpui-fast-overlay-first-mouse.diff`**: the overlay surface's view (`GPUIOverlayView`, which takes the pointer wherever an overlay is drawn over a native view) accepts the first mouse, as GPUI's own view does, by asking that view.
  Without it, in a window that is not key, the first click on a menu, the palette or a webview island's zoom controls over the page only brought the window forward, while the same click beside the page, or in the page, acted at once.
- **`gpui-fast-file-drop-modality.diff`**: a drag of files from Finder counts as pointer input.
  AppKit sends a window no mouse moves while another app's drag is over it, only the drag's own events, which GPUI turns into mouse moves and a release after it has noted the input's modality; so after typing, the window stayed in keyboard modality, which hides hover, and the drop's release found no element under the pointer: a file dropped on the Project tree or an editor did nothing.
  The drag's entering, moving and dropping now set the pointer's modality, as a mouse move does.
- **`gpui-fast-active-drag-type.diff`**: `App::has_active_drag_of::<T>()`, whether the drag in progress carries a `T`.
  GPUI only said whether anything was dragged, so the Project tree's and an editor's drop highlights, left by a Finder drag that went out of the window (which GPUI's elements never see) or by a drop on a row, came back for an unrelated drag such as the editor's split divider.
  They now show only while a drag of the kinds they take is in progress.
- **`gpui-fast-motion-and-type.diff`**: two things CSS has and GPUI lacked, which Lattice's look needs (`fast/scale.rs`, `fast/letter_spacing.rs`; upstream files get only hooks, as gpui-fast's own rules ask).
  - *Element scale*: `gpui::scaled(child).scale(s).origin(..).translate(..)`, CSS's `transform: translate() scale()` about a `transform-origin`, for the popup, dialog and toast entrances. Paint is transformed in the scene, every primitive kind, layer and rounded clip alike; layout and hit testing are not. Sprites are stretched from their raster at rest rather than rasterized at every fractional size, as a browser composites a transformed layer, so an entrance adds nothing to the atlas. A view replayed from last frame is replayed only under the scale it was drawn with, and a view drawn again inside a replayed one keeps the scale it is drawn under.
  - *Letter spacing*: `TextStyle::letter_spacing` and `Styled::letter_spacing` (pixels, rems, or a fraction of the font size, which is CSS's `em`), applied after shaping and keyed in the line layout cache, so wrapping and hit testing read the spaced glyphs.
- **`gpui-fast-interface-zoom.diff`**: a window's interface zoom, a webview's page zoom for GPUI (`fast/interface_zoom.rs`), which Settings › Appearance › Interface size and ⌘+ / ⌘− / ⌘0 need.
  `Window::set_interface_zoom(z)` multiplies the window's scale factor by `z` and divides its viewport by it, so the interface is drawn `z` times as large, rasterized at that size, and reflows into the window rather than being magnified past it.
  The platform keeps measuring in points: every event it delivers has its positions (and a pixel scroll delta) divided by `z` on the way in, the input method's caret and selection rectangles are multiplied by `z` on the way out (and the point it asks about divided), as are the window menu's position, the visual viewport and the platform's insets.
  Without a zoom set (1) the crate behaves as upstream.
  A native composition surface is placed from GPUI's device pixels, so it lands where its element is laid out; what a surface's owner puts inside it in points is that owner's to scale (`gpui-webview-interface-zoom.diff`).
- **`gpui-fast-backdrop-blur.diff`** (`gpui`, `gpui_apple` and `gpui_macos`): CSS's `backdrop-filter: blur()`, which the Tauri app's frosted popovers (`surfaces.css`) need (`fast/backdrop.rs` in each crate; upstream files get only hooks).
  `Styled::backdrop_blur(radius, fallback)` and `Window::paint_backdrop_blur` put a backdrop in the scene before the element's shadows and background: a polychrome sprite whose texture id (`BACKDROP_TEXTURE_INDEX`) no atlas allocates, as scroll layer tiles and rounded clip groups are carried, so every copy, replay, translation, element scale and split of a scene carries it at its draw order, and no primitive's layout or `PrimitiveBatch` changes (`gpui_wgpu` builds as it is).
  The sprite's tile holds the blur's standard deviation in device pixels (CSS's radius times the scale factor, so the interface zoom and an element scale scale it) and the fallback colour.
  The Metal renderer, in each loop that draws a frame's batches (upstream's, `fast::paths` and `fast::rounded_clip`), ends the render pass at a backdrop's batch, copies the target's pixels under it with a margin of three standard deviations, grown to whole 64 pixel steps within the target, into a texture the size of that region, blurs it with `MPSImageGaussianBlur` (its standard deviation rounded to half a pixel, so a backdrop scaling in or out reuses a few kernels and the same textures, and clamped at the region's edges, so it does not darken toward them), begins the pass again loading what it stored, and draws the blur back inside the rounded rectangle, the content mask and the enclosing rounded clips (`fast/backdrop.metal`).
  An overlay surface over native views (which draws all of a window's deferred content once the window holds any native surface) is on a layer of its own, so its backdrops blur the base surface's frame: `gpui_macos` keeps the base frame each frame an overlay holds a backdrop (`MetalRenderer::keep_frame_for_backdrops`), drawn first in the command queue the renderers share, and hands it to each overlay renderer with the bounds of the native views under it (`MetalRenderer::set_backdrop_frame`), which composites what it drew so far over the frame's region before blurring it.
  Where the target's pixels are not what is under the backdrop, the rectangle is filled with the fallback colour instead: an overlay's backdrop over a native view (whose pixels Metal cannot read), a scroll layer's tile (a scroll layer draws a backdrop over its tiles, as it does a path, so this is only a tile's own copy), the first frame of a layer whose drawables were framebuffer-only (it is asked for readable ones from then on), a device without Metal Performance Shaders, inside a `Window::paint_layer` (one draw order for everything, so the fallback is a quad there) and every platform but macOS and iOS.
  Without a backdrop in the scene the crates behave as upstream.
- **`gpui-fast-font-smoothing.diff`** (`gpui_apple`): glyphs are drawn without font smoothing, as WebKit draws them under `-webkit-font-smoothing: antialiased`, which the Tauri app sets on its root (`fast/font_smoothing.rs`).
  A CoreGraphics bitmap context smooths fonts unless told not to, and smoothing thickens every stem: upstream drew dark text at the context's default (smoothed) and light text smoothed at its strongest dilation, so the editor's Latin text came out about 15% heavier than the Tauri app's and Chinese in PingFang SC about 19% heavier, in the dark appearance 38% and 51%.
  Every glyph is now drawn with smoothing off, and no color asks for a dilation, whatever the user's `AppleFontSmoothing`.
- **`gpui-fast-glyph-outline.diff`** (`gpui` and `gpui_apple`): `WindowTextSystem::glyph_outline(font_id, glyph_id)`, a shaped glyph's outline in font units with y up (`GlyphOutlineCmd`, `fast/glyph_outline.rs` in each crate; upstream files get only the trait's hook and a forwarding method).
  GPUI draws a glyph only as a sprite rasterized upright, and the whiteboard rotates text elements as Excalidraw does; it shapes the text with GPUI as usual and draws the glyphs' outlines under the element's rotation, so the face is the one the shaper picked, CoreText's fallback fonts included.
  The outline is font-kit's (CoreText); the trait's default, which every other platform keeps, is `None`, as it is for a bitmap glyph (color emoji).
  Adapted from quiet.md's patch to gpui 0.2.2 (its `vendor/PATCHES.md` #37, MIT, Copyright (c) 2026 s1dashu, [s1dashu/quiet-md](https://github.com/s1dashu/quiet-md)), without its Windows and Linux outlines and synthetic-italic shear, which gpui-fast's text system doesn't have.
- **`gpui-base-popover-exit.diff`**: a popover that plays its way out.
  `Popover::exit(duration)` keeps the content drawn for that long after the popover closes, as it was, under a cover that takes its presses, with no focus, Escape or dismissal; `PopoverState::leaving()` tells the content builder how far into the exit it is, so Lattice's popovers draw their exit (`pop_out`) where the Tauri app's `popup-motion.css` plays one.
  Without `exit` the crate behaves as upstream.
- **`gpui-base-max-length.diff`**: `InputState::max_length(n)`, HTML's `maxLength` for a Kit input.
  An insertion (typed, pasted, or a composition when it is committed) is cut to the room the rest of the text leaves before it is applied, and a keystroke at the limit inserts nothing, so the edit is one ordinary step of the undo history; Lattice's workspace rename field (24 characters) and Save a local template's name and version (300) had clipped after the fact with `set_value`, which cleared the field's undo history.
  Without `max_length` the crate behaves as upstream.
- **`gpui-webview-interface-zoom.diff`**: a webview island at another interface size.
  The surface sits where GPUI laid the page out, but gpui-webview set the WKWebView's frame inside it from GPUI's pixels as if they were points, so at 120% the page covered only part of its island and below 100% it was clipped.
  The frame and its offset are scaled by the window's interface zoom, and the page is zoomed with the interface (on top of `WebView::set_zoom`'s own zoom), so it keeps the island's size in its own pixels, as the Tauri app's interface zoom zooms its pages.
  This is macOS with `gpui-fast` only; elsewhere the crate behaves as upstream.
  The `e2e` scenario checks the page's frame and viewport at 120% and 90%.
- **`gpui-component-lattice-hooks.diff`**: two seams for Lattice's design system, each inert until the app uses it.
  - *A host-drawn menu highlight*: with a `GlobalMenuHighlight` installed, a `PopupMenu`'s rows draw no hover or selection fill of their own; the menu records each row's bounds, section (rows between two separators or labels) and whether it can be highlighted as it is laid out, and hands them with its highlighted item to the host's `MenuHighlight::paint`, behind the rows.
    Lattice draws the fluid hover there (`lattice_ui::fluid_hover::KitMenuGlide`): one fill gliding between rows, as the Tauri app's menus have it.
    Without the global the menu is upstream's.
  - *`Tree::scrollbar(false)`*: the tree leaves out its own scrollbar, so a host can draw one over `TreeState::scroll_handle` (Lattice's hover-revealed scrollbar, `lattice_ui::scrollbar`).
    The default draws it, as upstream.
- **`gpui-component-overlays.diff`**: GPUI Kit's notification and sheet layers are drawn `deferred`, as its dialogs already are. gpui-fast composes native views (a webview island) between a window's base content and its overlay surface, and only deferred draws reach the overlay surface, so without this a toast or a Kit sheet is covered by any webview under it.

The new public API (`scaled`, `Scaled`, `TextStyle::letter_spacing`, `Styled::letter_spacing`, `Window::set_interface_zoom`, `Window::interface_zoom`, `App::has_active_drag_of`, `WindowTextSystem::glyph_outline`, `GlyphOutlineCmd`, `Styled::backdrop_blur`, `Window::paint_backdrop_blur`, `BackdropBlur`, `Backdrop`, `BACKDROP_TEXTURE_INDEX`, `is_backdrop_texture`) is not gpui-fast's, which adds no public API without its maintainers' agreement; it is kept here, on the pin, until it is upstreamed or replaced.

## Moving a pin

1. Change the pin in `script/check-patches`, in the workspace manifest's `[patch]` tables and in `gpui-fast-vendoring.diff`.
2. Run `script/check-patches --write`; a diff that no longer applies fails it, and is fixed against the new upstream.
3. Run the patch tests in a gpui-fast checkout at the new pin with the diffs applied; this is required, because a diff can still apply and build after upstream moved what it hooks into. From a directory holding the checkout as `gpui-fast/`:

   ```sh
   for diff in gpui-fast-lab-occlusion gpui-fast-motion-and-type gpui-fast-overlay-first-mouse gpui-fast-interface-zoom gpui-fast-lab-assume-key gpui-fast-backdrop-blur gpui-fast-font-smoothing gpui-fast-glyph-outline; do git apply "<lattice>/gpui/patches/$diff.diff"; done
   (cd gpui-fast && cargo test -p gpui --lib --features test-support,gpui_platform/runtime_shaders -- fast::scale fast::letter_spacing fast::interface_zoom fast::backdrop)
   (cd gpui-fast && cargo test -p gpui_apple --lib --features runtime_shaders,font-kit -- fast::backdrop fast::font_smoothing fast::glyph_outline)
   ```

   `fast::scale` covers the transform of every primitive kind, nesting, the kept outer clip, and a view replayed inside a scale or drawn again inside a replayed one; `fast::letter_spacing` covers the spacing of clusters and marks and the measured width of tracked text; `fast::interface_zoom` covers the conversion of events and of the input method's rectangles, and a zoomed window's viewport and scale factor; `gpui`'s `fast::backdrop` covers a backdrop's draw order between what is under it and its element, and its blur under an element scale and the interface zoom, and `gpui_apple`'s draws backdrops headlessly and reads the pixels back (blurred inside the rounded rectangle and the content mask only, not darker at the edges, the fallback where the target cannot be read, and an overlay's backdrop blurring the base frame with the overlay's own pixels over it, or filling the fallback over a native view), and `gpui_apple`'s `fast::glyph_outline` reads a shaped glyph's outline back (its contours, inside the glyph's typographic bounds). CI's `gpui-patches` workflow runs the same.
4. Build, run the workspace tests and the `e2e` scenario.
