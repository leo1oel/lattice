# The Agent

One of the features [the GPUI app](../README.md) has so far.

Runs the Agent as the Tauri app embeds it: Synara's panel beside Project, its Git workspace (the titlebar's Git button, or a turn's Review) as a tool panel among the documents, with its Changes and Pull requests tabs, and Settings › Providers, Synara's own settings page for the open project, which the Agent's provider settings open on the place they name.
The composer's measured width is the Agent panel's minimum, so the dock never narrows the panel past its controls.
Each is the Agent island's page (`islands/agent`), the Tauri app's own Synara host (`src/app/use-synara-host.ts`) with Synara's frame in it, so the frame speaks to it over the same postMessage protocol; what the host asked of the Tauri app's window comes to the GPUI app over the island bridge (`crates/lattice-gpui/src/agent/`): the file the Agent names opened, the editor in front with its caret and selection (the host context), Synara's notifications on the app's stack with their buttons, its confirmations in the app's dialog, the app's shortcuts pressed in the frame, and the theme and accent, which the page reads from the app's own stylesheets as the Tauri app does, so nothing styles the Agent from outside.
The service is lattice-core's supervisor, unchanged: it starts only inside the macOS bibliography sandbox, which denies every `.bib` write from the Agent's processes, and is off elsewhere, as in the Tauri app; the Agent's bibliography changes go through the app, which takes only lattice-core's `cite` and `upgrade_bibliography` and a reference removal the writer confirms, for the panel's own project only.
Its tools on the window's documents run where the Tauri app runs them, on the open editor that registered for them: the canvas tools on the board shown in front, the range tools on the sheet they name (a sheet that is not open is read and written on disk), a page preview through an open deck or, with none, through Open Slide itself; each call goes from the Agent's page to the document's own page, where the Tauri app's executor runs (`crates/lattice-gpui/src/shell/agent_documents.rs`, `islands/shared/agent-tools.ts`). A board or sheet the Agent creates is created as the Project pane creates one and opened, and the Agent hears back once its editor has registered.
Its paper library is the project's papers, read again when they change; its annotation tools and its view of the project's comments work on the project's annotations (and an Overleaf-linked project's threads), through the window's own annotations store, the file's one writer, as the Tauri app's Agent works through its window's comments store (`crates/lattice-gpui/src/agent/surface/annotations.rs`).
The page reads the notes and rounds from the store, hears every change the store makes, and hands back each change it makes as what it added, changed or removed, which the store applies by id to what it holds; so a note the Annotations panel wrote after the page last heard is kept, and a proposal the Agent records is the one the Tauri app's review shows.
Its checkpoints come to the window as the Tauri app's `useAgentCheckpoints` takes them (`crates/lattice-gpui/src/agent/checkpoints.rs`, `shell/agent_checkpoints.rs`): the History panel's checkpoint rows, a build once a turn's fresh edits rest for 1.5 s (with Automatic builds) or at once after an Undo, each build telling the turns it covers how it went, and the panel reopening on the thread its checkpoints are of.
What it is told of the window is what the Tauri app's `useAgentContext` tells it (`agent/host_context.rs`, `shell/agent_context.rs`): the file in front, whatever it is; the editor or a PDF as the surface worked in, as focus moves; the compiled PDF's page and page count; one shared selection, the source editor's (with its lines), the visual Markdown editor's, a PDF's (a project PDF's with its path and page) or a paper's in its reader; Open Slide's deck and slide while a deck is in front; and a paper in its reader while that reader is the one worked in (its view or its text focused, and still after the keyboard moves to the Agent's composer), as `activePaper` with the text it shows, Blog or Paper, so the Agent is told the paper, its reading file and its original PDF instead of a Markdown file.
Its turn is the window's while it runs or waits (`shell/agent_turn.rs`): switching to another project asks before interrupting it, the open decks light up for it, and its start marks Get started's Agent step; the writer's saves, an Overleaf sync's writes and a resolved conflict are reported to it as Lattice's own (`agent/host_writes.rs`), so its Undo keeps them.
Its header carries the Tauri panel's permission picker once the frame reports its mode (`agent/surface/permission.rs`): Never ask, Ask for risky actions (faded and inert while the provider cannot run it) and Ask before outside edits and network, with Pi's endpoint note while a model endpoint is saved; the choice goes to the frame, and the frame's own report moves the picker. The surface's `permission()` and `set_permission_mode()` are the window's one copy of the mode, for anything else that needs it.
Until its page draws, the panel shows the Tauri app's `AgentPanelSkeleton`, drawn natively on the sidebar's ground after the loading clock's delay (`agent/surface/skeleton.rs`).
Files dragged from the Finder onto the panel go to its composer as the Tauri app's window sends them: the island takes the drag from WebKit (`lattice-webview`'s `island/file_drops.rs`), so the frame never sees it; the page lights the panel while files the Agent can read are over it and, on the drop, has the app read that drop's files, and only those, into the composer as its "+" menu would add them (`agent/surface/drops.rs`, `islands/agent/drops.ts`).
The composer's microphone works as it does in the Tauri app: its frame may use the microphone, and the webview grants it, leaving the decision to macOS. A packaged GPUI app needs `NSMicrophoneUsageDescription` in its `Info.plist`, as `src-tauri/Info.plist` has it, or macOS ends the app when the microphone is first used; run from a terminal, the terminal's own permission covers it.
The panel's page never hibernates, so a turn keeps running behind another tab. The runtime is the one the Tauri app stages (`node scripts/prepare-synara-sidecar.mjs` into `src-tauri/synara-runtime`, or `LATTICE_GPUI_RESOURCES`); without it the panel says the bundled runtime is missing. The Agent's home is the GPUI app's own (`<data>/lattice-gpui/synara`), so its threads and settings start apart from the Tauri app's.
