# The Agent

One of the features [the GPUI app](../README.md) has so far.

Runs the Agent as the Tauri app embeds it: Synara's panel beside Project, its Git workspace (the titlebar's Git button, or a turn's Review) as a tool panel among the documents, with its Changes and Pull requests tabs, and Settings › Providers, Synara's own settings page for the open project, which the Agent's provider settings open on the place they name.
The composer's measured width is the Agent panel's minimum, so the dock never narrows the panel past its controls.
Each is the Agent island's page (`islands/agent`), the Tauri app's own Synara host (`src/app/use-synara-host.ts`) with Synara's frame in it, so the frame speaks to it over the same postMessage protocol; what the host asked of the Tauri app's window comes to the GPUI app over the island bridge (`crates/lattice-gpui/src/agent/`): the file the Agent names opened, the editor in front with its caret and selection (the host context), Synara's notifications on the app's stack with their buttons, its confirmations in the app's dialog, the app's shortcuts pressed in the frame, and the theme and accent, which the page reads from the app's own stylesheets as the Tauri app does, so nothing styles the Agent from outside.
The service is lattice-core's supervisor, unchanged: it starts only inside the macOS bibliography sandbox, which denies every `.bib` write from the Agent's processes, and is off elsewhere, as in the Tauri app; the Agent's bibliography changes go through the app, which takes only lattice-core's `cite` and `upgrade_bibliography` and a reference removal the writer confirms, for the panel's own project only.
Its tools on the window's documents run where the Tauri app runs them, on the open editor that registered for them: the canvas tools on the board shown in front, the range tools on the sheet they name (a sheet that is not open is read and written on disk), a page preview through an open deck or, with none, through Open Slide itself; each call goes from the Agent's page to the document's own page, where the Tauri app's executor runs (`crates/lattice-gpui/src/shell/agent_documents.rs`, `islands/shared/agent-tools.ts`). A board or sheet the Agent creates is created as the Project pane creates one and opened, and the Agent hears back once its editor has registered.
Its paper library is the project's papers, read again when they change; its annotation tools and its view of the project's comments work on the project's annotations (and an Overleaf-linked project's threads), which the Agent's page holds and saves as the Tauri app's comments store does, so a proposal it records is the one the Tauri app's review shows.
The panel's page never hibernates, so a turn keeps running behind another tab. The runtime is the one the Tauri app stages (`node scripts/prepare-synara-sidecar.mjs` into `src-tauri/synara-runtime`, or `LATTICE_GPUI_RESOURCES`); without it the panel says the bundled runtime is missing. The Agent's home is the GPUI app's own (`<data>/lattice-gpui/synara`), so its threads and settings start apart from the Tauri app's.
