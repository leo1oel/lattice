# The PDF preview

One of the features [the GPUI app](../README.md) has so far.

Shows the PDF on the right, rendered natively by PDFium, in the Tauri app's viewer: page navigation and a typed page, Back and Forward over link jumps, the outline, Find in PDF (Match case, Whole word, the match counter), zoom steps, a typed zoom, ⌘-wheel / Ctrl-wheel and pinch around the pointer, Fit width and Fit height, dark pages and Save PDF as…; a toolbar 640px or narrower folds the secondary controls into a ⋯ menu, as the Tauri app's does. A drag selects text and ⌘C / Ctrl+C copies it; a link jumps (Back returns) or opens in the browser. A rebuild redraws only the pages it changed. The live PDF can move into a window of its own, which opens again, behind the workspace, when the project opens next; each other root document built keeps its last PDF in a tab of its own; a PDF of the project opens from the tree in a tab among the documents.
An image of the project (PNG, JPEG, WebP, SVG) opens from the tree in the Tauri app's image preview, in a tab of its own: fitted on its checkerboard stage at 100%, zoomed from 30% to 500% by its controls (Zoom out, a typed or wheeled percentage, Zoom in), ⌘-wheel / Ctrl-wheel and pinch, its zoom and scroll kept for the session; any other file lattice-core reads as binary (EPS, GIF, a font, an archive) says "This format cannot be rendered in the preview", as the Tauri app's does.
It jumps between the PDF and the source with SyncTeX: ⌘⇧J / Ctrl+Shift+J (or the PDF toolbar's locate button) marks the caret's line in the PDF, a double-click in the PDF opens its source line, and an Outline row opens its heading and marks it in the PDF; the Outline marks the section the caret of the editor in front is in.

## In the e2e scenario

Its PDF steps write and build a second root document of twelve pages (`scenario/e2e/pdf/`): its PDF becomes the live one and main.tex keeps a tab of its own; then the outline (its heading lines kept past a comment block of wide characters), page navigation and a typed page, zoom and both fits, ⌘F / Ctrl+F with the query typed and Enter, a section link clicked with the native mouse and undone with Back (and links to a file or an app's own scheme left unfollowed), a selection dragged with the native mouse and copied with ⌘C / Ctrl+C, dark pages, a rebuild that changes one page and redraws only that one, the page window letting go of far pages, and the separate window, opened again when its project is shown again and leaving a panel it shares with Project on screen at its width with Project in it, and main.tex's tab asking for a build that Stop then drops, so the next build compiles the document in front; building main.tex again trades the two tabs back. Then a second main window opens on the project, and its PDF must load and draw at the window's scale factor, through the same process-wide PDFium worker.
