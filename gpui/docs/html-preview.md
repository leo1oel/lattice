# HTML files

One of the features [the GPUI app](../README.md) has so far.

Shows an HTML file as the Tauri app does, in Preview until another view is chosen (Edit, Split and Preview in its strip and its ⋯ menu, each file keeping its own): the Tauri app's sandboxed preview (its images and embedded pages loaded, relative links disabled, web links to the browser) in a webview island, following the editor 180 ms after typing pauses, with its zoom (50% to 200%, or typed) and Lattice's scrollbar drawn over the page, and its reading position and zoom kept across edits and views. The islands are below.

## In the e2e scenario

The `islands` scenario: the webview island checks the `e2e` scenario also runs on macOS, alone, for work on the islands (an HTML file's Preview): it opens an HTML file and checks that its island is built on first show and revealed once loaded, that the asset protocol serves the image the host granted, that the page's scroll and a zoom cross the bridge (a native click on the zoom controls over the page reaching GPUI), the page's view covering the island and the page zoomed with the interface at 120% and 90%, the theme, that a native click gives the page the keyboard and ⌘K / Ctrl+K typed there opens GPUI's palette, that a toast over the page is drawn above it (macOS, from a composited capture of the window, skipped where the screen cannot be captured), Edit, Split and Preview, a tab switch hiding the page, and its hibernation and return; then the board, spreadsheet and deck islands on the tutorial's own (`scenario/e2e/structured.rs`): a sheet's edit typed with native keys saved, its Excel export, its confirmation as GPUI's dialog above the page, and its hibernation; a board following the theme, an edit on disk merged in and a shape drawn with native input saved as its tab closes; and a deck framing the Open Slide runtime's origin, or saying it could not start without the runtime. It then opens a Markdown file (`scenario/e2e/markdown.rs`) and checks its highlighted source, the visual editor drawing its heading, maths, table and image (and not its front matter), that opening it writes nothing, that a word typed into the visual editor with native keys is saved as exactly that word, that ⌘Z typed there undoes it through the buffer, that text typed into the source reaches the visual editor, Preview and a jump to a line landing in it, a move in the tree and back rebasing its image link to the same figure, its hibernation and return, a word typed just before its tab closes being saved, in Split each side following the other's scroll on a long file (`scenario/e2e/markdown_scroll.rs`), and the visual editor's `[[page#` completion offering a page added to the project and, once that page's text changes on disk, its new heading, but not a page the project tree leaves out (under `node_modules/` or `.github/`) though the watcher reports it (`scenario/e2e/markdown_pages.rs`).
