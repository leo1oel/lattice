Where to start. If you want the *why* behind the structure, read
[`architecture.md`](architecture.md) first; this document is the index.

Counts and line numbers in this file were measured against the **working tree**
at `v0.1.229`, mid-refactor — file counts and line counts here are a snapshot of
a tree that is moving, not a contract. `src/App.tsx` in particular is being
actively split into `src/app/` hooks and its line numbers shift between commits.
Re-measure before quoting anything from this page; every figure below is
reproducible with the `rg` / `git ls-files` / `wc -l` command implied by its
description.

## 3. Navigating `src/`

`src/` was, until recently, 322 files in one flat directory. It is now split by
domain: **12 files remain at the root** and everything else lives in a
directory named for what it does. The split landed in two batches —
`overleaf/` + `collab/` first, then the remaining 215 files — and both were
pure `git mv` renames, so `git log --follow` still reaches the whole history of
every file.

Two rules govern the layout, and both are deliberate:

- **Files were placed by their reference relationships, not their names.** The
  test for "shared" is not how many modules import something but whether its
  importers span more than one domain. That is why `spreadsheet-types.ts` sits
  in `editor/spreadsheet/` despite 9 importers, why `references-panel.tsx` (a
  *symbol*-reference panel, not a bibliography one) sits in `project/`, and why
  the peer-colour palette moved out of `collab/` into `components/ui/`.
- **Filenames keep their prefix** — `src/collab/collab-session.ts`, not
  `src/collab/session.ts`. Dropping the prefix would rewrite every intra-domain
  import and turn a reviewable pure-rename diff into a content diff.
  Prefix-stripping is a separate pass.

### What stays at `src/` root

Twelve files, and the bar is "the application shell, or a contract every domain
depends on". There is no `shared/` directory: a grab-bag named `shared` attracts
files, and a root you can read in one screen does not.

| `main.tsx` | The Vite entry. `index.html` names `/src/main.tsx` literally. |
| `App.tsx`, `App.css`, `App.test.tsx` | The root component and its stylesheet. `App.css` is the `@import` hub for `src/styles/*.css`. |

## 4. Vendored code — read before editing

Two directories under `src/` are not written by this project.

### `src/open-knowledge-app/` — auto-vendored

- **Source**: `https://github.com/inkeep/open-knowledge`, `packages/app/src`.
- **Sync script**: `scripts/vendor-open-knowledge.mjs`. The file list is a
  `const MANIFEST` array **inside that script** (starts at
  `scripts/vendor-open-knowledge.mjs:41`) — there is no separate manifest file.
- **Commit pin + content hashes**: `open-knowledge-app.lock.json` at the repo
  root. It records `upstream`, `commit`, `sourceRoot`, `vendoredAt`, and a
  per-file hash.
- The script rewrites imports on the way in: `@/…` → `@ok-app/…`,
  `@inkeep/open-knowledge-core` → `@ok-core`, and the `@lingui/*` macros onto
  local shims — the whole `REWRITES` table is
  `scripts/vendor-open-knowledge.mjs:238-245`. Those aliases are declared in
  `vite.config.ts`, `vitest.config.ts` and `tsconfig.json`.
- Verify without writing: `node scripts/vendor-open-knowledge.mjs --check`.

**Local patches are accepted practice**, and there is an established convention
for them ("Local seam — not upstream code" headers). But **re-vendoring can
overwrite them** — the lock's note says so outright. Prefer making changes
outside the vendored tree; if you must patch inside, add the seam header so the
next re-vendor is a visible conflict rather than a silent revert.

### `src/open-knowledge-core/` — related but NOT auto-synced

The editor subset of upstream's `packages/core/src`. No script syncs it and it
is not in the lock file. Treat it as owned-but-derived code: 200 files, ~37.5k
lines, of which ~35.3k are TypeScript.

This tree was recently pruned hard — it was 256 files and ~181k lines, the bulk
of that being checked-in Markdown perf fixtures under `markdown/fixtures/perf/`.
Those fixtures are gone; `markdown/fixtures/perf/` now holds only the generator
(`generate.ts` + `generate.test.ts`) and all of `markdown/fixtures/` is under
2k lines. Older notes that describe this directory as ~181k lines or that point
at `util/doc-name.ts` are stale — the helper is at
`src/open-knowledge-core/utils/doc-name.ts`.

### Licensing

Both trees are **GPL-3.0-or-later** and each carries its own `LICENSE` file.
Lattice as a whole is GPL-3.0-or-later precisely because these are linked into
the shipped binary (`src-tauri/Cargo.toml:7-9` says so). Adaptation headers and
the `LICENSE` files must be preserved. Attribution is recorded in
`THIRD_PARTY_NOTICES.md`.

The two trees carry two different upstream commit pins, and that is correct, not
a discrepancy:

## 6. Known rough edges

Stated plainly so you are not surprised.

### `App.tsx` is a ~9,760-line god component, currently being taken apart

It holds roughly **151 `useState`** calls, 130 `useCallback`, 103 `useRef`, 62
`useEffect`, and 27 `useMemo`, and exports exactly one thing: `default App`.
Nearly every feature's state still lives here. (Those counts are `rg -c`
against a file that is changing daily — re-measure, do not quote.)

There is an extraction pattern and it works. The first round pulled small,
self-contained slices into standalone hooks: `useAppearance`
(`src/settings/use-appearance.ts`, 90 lines), `usePanelLayout`
(`src/app/use-panel-layout.ts`, 169) and `useSynaraRuntime`
(`src/agent/use-synara-runtime.ts`, 78). The round in flight is much bigger and has
its own directory, `src/app/`: `use-collab-v2-session.ts` (841) and
`use-overleaf-workspace.ts` (960) between them lift ~1,800 lines of collab and
Overleaf state out of the hub. The direction is: **extract a cohesive slice
into a hook under `src/app/`, keep `App.tsx` as the composition point.**

Be honest about both halves of the trend.

- The growth was real and fast. `App.tsx` was 914 lines in the first commit
  that contained it (2026-07-15) and 11,074 lines at `HEAD` a month later
  (2026-08-17) — roughly 12× in a month, with extraction losing badly to
  feature growth for most of that period.
- The extraction is now ahead, for the first time. The working tree has
  `App.tsx` at ~9,760 lines with another ~1,800 in `src/app/`. That is the
  first sustained decrease in the file's history, and it is not finished.

If you add a feature here, extract one too.

### `document-canvas.tsx` is 4,461 lines

Same shape, one level down. It is large enough that Fast Refresh became a
problem: `src/canvas/canvas-lazy-modules.ts` exists specifically so that
`document-canvas.tsx` exports components *only*, because "one shared function
export there invalidates the whole module on every edit, and it is the largest
file in the app" (`src/canvas/canvas-lazy-modules.ts:4-7`).

### The lint debt is concentrated

`pnpm lint` runs `eslint src --max-warnings 128`. The cap is a ratchet: lower
it when you remove warnings, never raise it.

The warnings are almost entirely `react-hooks/*` diagnostics that
`eslint.config.js:45-55` deliberately downgrades to warnings
(`exhaustive-deps`, `refs`, `set-state-in-effect`, `immutability`), and
`react-refresh/only-export-components`. **(Unverified: the exact split — the
claim that `App.tsx` and `document-canvas.tsx` together account for 86 of 127
warnings could not be confirmed, since running lint was out of scope for this
document. The shape of the config and the size of those two files make it
plausible; measure before quoting a number.)**

### Test files that do not name what they test

Four files that misreported their subject were renamed in August 2026, and the
gap the worst of them hid is now closed: `navigator.test.ts` tested
`project-tree-git.ts`, so the 1,736-line `navigator.tsx` looked covered while
having no test at all. It is now `project-tree-git.test.ts`, and
`navigator.test.tsx` plus `navigator-drag.test.ts` cover the navigator itself.
The others became `collab-session-peers.test.ts` and `app-utils-confirm.test.ts`;
`latex-outline-breadcrumb.test.ts` was merged into `latex-outline.test.ts`.

Some test files still have no same-named source module, and those are fine —
they assert across several modules or on files rather than testing one export:
`src/collab/collab-live.integration.test.ts`,
`src/styles/editor-selection-styles.test.ts`,
`src/editor/latex/texcount.test.ts`,
`src/platform/pre-react-polyfills.test.ts`,
`src/platform/react-compiler-guard.test.ts`,
`src/platform/tauri-security-config.test.ts`,
`src/history/history-drawer-multifile.test.tsx`,
`src/components/ui/motion-controls.test.tsx`,
`src/pdf/pdf-viewer-component.test.tsx`,
`src/editor/markdown/visual-link-preview.test.tsx`. Most of these are
intentional (a scenario suite, not a unit suite) — but you cannot infer what a
test covers from its filename here. Open it.

The three that assert on *files* rather than exercise a module —
`react-compiler-guard`, `tauri-security-config`, `pre-react-polyfills` — live in
`src/platform/` because what they pin is the build/runtime platform, not any
feature. The fourth of that shape, `editor-selection-styles`, sits in
`src/styles/` because its subject is a stylesheet there.

### The `v2` suffix on `collab-*` is vestigial

v2 is the only room type; there is no v1 code path left (see
[`architecture.md` §3.9](architecture.md#39-the-v2-suffix-is-vestigial)). The
suffix survives because renaming touches 28 filenames and 62 files that
reference a `v2` identifier, plus the `protocol/` module name, the Durable
Object binding names, and the `/v2/` HTTP prefix — i.e. it is a
wire-compatible-migration problem, not a rename.

### Other things worth knowing

- **`src/` has no `@types/node` by design** — it is browser-only by convention.
  Vendored code that touches `process.env` is served by a hand-written ambient
  declaration, `src/open-knowledge-core/vendor-globals.d.ts:8`
  (`declare var process: { env: Record<string, string | undefined> };`).
  `src/open-knowledge-core/index.ts` is a pure re-export barrel with no
  `process` reference in it at all.
- **`src/styles/editor-workspace.css` is 2,036 lines**, the largest stylesheet;
  `src/App.css` is a 10-line import manifest, so don't look for CSS there.
- **`src-tauri/src/semantic_search.rs`** (1,690 lines) has neither incoming nor
  outgoing intra-crate dependencies. It is reachable only through its four
  commands and can be read in isolation.
- **The comment at `src/canvas/canvas-lazy-modules.ts:6` calls `document-canvas.tsx`
  "the largest file in the app".** That stopped being true once `App.tsx`
  passed it; the *reasoning* in the comment (a shared function export
  invalidates the module on every Fast Refresh edit) still holds.
